## 1. Inspect & Visualize (Headless Blender)
- **Inspect JSON:**
  ```powershell
  & "C:\Program Files\Blender Foundation\Blender 4.5\blender.exe" -b "<file.blend>" -P "C:\Users\joshe\AppData\Roaming\SpaceEngineers\Mods\.agents\skills\seut-blend\scripts\inspect_blend.py" -- "<scratch>\report.json" --islands
  ```

  Flags: `--islands` (adds spatial-merged sub-component bbox/material summaries for edge-split meshes), `--island-mesh "<ObjName>"` (repeatable filter), `--island-tol 0.001`, `--object "<ObjName>"` (repeatable; only those objects go in `objects`; island lists of a big imported mesh are still ~100+ KB, so read them via `--print-islands`, not the JSON), `--print-islands [--min-faces 20]` (prints one `ISLAND <obj> f=<n> min x y z max x y z mats` line per island to stdout; usually all you need, no JSON digging), `--profile "<ObjName>"` (repeatable; prints `PROFILE` min/max of `--profile-up Z` per `--profile-slice 0.05` slice along `--profile-axis Y`, optionally only verts with `--profile-limit X=0.46`; mesh-local coords. Use it to fit a roof or cover over existing geometry). Query JSON in sandbox with PowerShell `Get-Content ... -Raw | ConvertFrom-Json` (avoid reading huge JSON files raw; `python.exe` Store alias is blocked in sandbox). Island `min`/`max`/`center` are numeric arrays: index them (`$_.min[1]`). Don't string-split them; PowerShell only *displays* arrays space-joined.
  Typical part-finding call: `... inspect_blend.py -- "<scratch>\r.json" --object TurretBase2 --print-islands --min-faces 20`.
- **Render 2×2 Contact Sheets** (then inspect PNGs via `read_file`):
  ```powershell
  & "C:\Program Files\Blender Foundation\Blender 4.5\blender.exe" -b "<file.blend>" -P "C:\Users\joshe\AppData\Roaming\SpaceEngineers\Mods\.agents\skills\seut-blend\scripts\render_blend.py" -- --scene "Turret" --assemble --output "<scratch>\preview.png"
  ```
  Flags: `--all-scenes`, `--scene "<name>"`, `--collection "<name>"` (e.g. `BS1 (Turret)`), `--assemble` (`--pitch <deg>` pitches Base2 or 2-stage elevation Barrels subparts), `--hide-linked` (hide `(L)` child-subpart previews so a subpart scene like `Base1` isn't hidden behind its barrels), `--bottom` (underside/rear views), `--show-collision`, `--clay`, `--no-empties`, `--no-grid`, `--size 640`, `--samples 16`. Panels on mostly-light models read best at `--samples 16–24`; subparts that sit between big pods are shadowed, so judge material contrast on `--hide-linked` renders.
  **Close-up mode** (needed to judge greebles, rivets, seams and small gaps; the 2×2 panels are too small for that): `--camera x,y,z [--target x,y,z] [--lens 40] [--width 1000 --height 750]` renders ONE perspective image from that point (scene world coords; with `--assemble`, the assembled scene's coords). `--target` defaults to the bbox centre. Add `--no-grid --no-empties --samples 32–40`. For a subpart scene (Base2: +Y forward), front quarter ≈ `--camera 1.35,1.45,1.0 --target 0,0.05,0.25`, rear quarter ≈ `--camera -1.3,-1.35,1.1`, side ≈ `--camera 1.7,0.25,0.45`. Small dark slivers, notches or rectangles in close-ups are usually real geometry problems (folded inset outline, a part poking through an angled edge, a void under a cap), not render noise.
- **Subpart clearance sweep** (run after ANY change to a turret base/subpart; use the `.sbc` `<Min/MaxElevationDegrees>`):
  ```powershell
  & "C:\Program Files\Blender Foundation\Blender 4.5\blender.exe" -b "<file.blend>" -P "C:\Users\joshe\AppData\Roaming\SpaceEngineers\Mods\.agents\skills\seut-blend\scripts\check_clearance.py" -- --static-scene MissileTurretBase1 --pivot-empty subpart_MissileTurretBarrels --min -58 --max 90 --json "<scratch>\clear.json"
  ```
  Rotates every island AABB of the linked moving scene about the pivot empty's local `--axis` (default `X`) and reports static samples inside them (`CLASH {...}` per island with `deg_range`, `static_z_range`, `static_meshes`). AABBs are conservative. Hits on hub/axle islands the static part deliberately encloses are expected. Real problems are hits on the big pod/barrel islands above deck level. Flags: `--moving-scene`, `--step 2`, `--shrink 0.003`, `--ignore-mesh <name>` (repeatable).
  - **`--exact`**: true triangle-vs-triangle overlap per angle (`BVHTree.overlap`), replacing the AABB sweep. It prints `EXACT {moving_mesh, static_mesh, tri_pairs, deg_range, moving_local_min/max}` or `EXACT none`. Use it to settle AABB hits on curved or rotated islands, such as a tub or shroud around the pivot, whose box corners stick out past the real surface. Those were false positives on every run of the autocannon frame. A part fully buried inside another without the surfaces touching is not reported (it's invisible anyway).
  - **`--radius-report [--slice 0.05]`**: an angle-independent check for anything that rotates about the pivot axis. Per slice along the axis it prints `RADIUS {moving_r_max, static_r_min, margin}` for slices with margin < 0, plus `RADIUS_WORST`. Margin ≥ 0 everywhere means nothing can touch at ANY elevation. Margin < 0 only means a contact is possible somewhere in a full turn; the sweep or `--exact` decides whether it happens inside the sbc limits. Design rule: keep new rotating geometry inside the smallest static `r_min` of its band (e.g. the gatling yoke's lowest bars are 0.79 m from the trunnion axis), so it clears automatically.

- **Write a scratch working copy back to `Models\`:**
  ```powershell
  & "C:\Program Files\Blender Foundation\Blender 4.5\blender.exe" -b "<scratch>\work.blend" -P "C:\Users\joshe\AppData\Roaming\SpaceEngineers\Mods\.agents\skills\seut-blend\scripts\writeback_blend.py" -- "<Mods>\Models\large\X.blend" --expect-sha256 <hash of your backup> --backup-to "<scratch>\work"
  ```
  `--backup-to DIR` copies the current target to `DIR\X_latest_backup.blend` (rolling) before saving and prints `BACKUP <path> <sha>`. After saving it prints `NEWSHA256 <hash>`. Use that as `--expect-sha256` for the next write-back of the same file. The saved hash never equals your scratch copy's hash, because paths are remapped on save. Iteration loop: build script opens `Models\X.blend` read-only (`-b`), `save_as` to `<scratch>\work\vN.blend` → `update_subparts.py --save` → checks/renders → `writeback_blend.py --expect-sha256 <last NEWSHA256> --backup-to <scratch>\work`.

Blender leaves the previous version as `X.blend1` (git-ignored via `*.blend1`; it's the user's one-step undo).
- **Procedural mesh helpers (`scripts/procgen.py`):** `MeshBuilder(material_names)` with `box/cyl/ring/prism/tube/beam/add_mesh/to_mesh`, `panel_outline()` (pedestal-style chamfered-top panels) and `bezier()`. Import with `sys.path.insert(0, r"...\seut-blend\scripts")`. It already handles material-before-bevel, the single `UVMap` box projection, sharp-edge marking, and keeping source UVs for `add_mesh` faces. Use it instead of hand-rolling bmesh primitives. Also in `procgen.py`:
  - **Armour shapes:** `B.loft(outline, a0, inset(outline, d), a1, mat, axis='X')` gives a plate whose outer face is inset by `d`, so all edges are angled. It reads as armour, not a slab; `d` ≈ 0.025–0.035 for a 7–9 cm plate. `inset()` (convex outlines only) asserts when an edge shorter than `d` would fold. A fold shows up as a dark spike at a corner, so lengthen that edge or reduce `d`. Use `ngon(apothem, 8)` for faceted housings around an axle and `arc(r, a0, a1, n)` for curved tubs and the bottoms of outlines.
  - **Greebles:** `B.riveted_plate(matrix, hx, hy, VDARK, CHROME)` makes a plate with a rivet ring, sunk 4 mm so it never floats on a bevel. Place it with `Matrix.Translation(p)` on a flat top, `Matrix.Translation(p) @ FACE_FRONT` / `FACE_REAR` on ±Y faces, or `slope_frame(p_hi, p_lo)` on a sloped face of an X-extruded profile.
  - **Existing SE meshes:** `spatial_islands(me)`, `island_bbox(me, isl)` and `island_faces_within(me, lo, hi)` select whole parts. Use them, not a per-face centre test, to lift a part out of another mesh: the per-face test grabbed a stray face of a neighbouring shelf. Then `B.add_mesh(src_me, matrix=..., face_filter=lambda f: f.index in keep)` copies it with its UVs.
  - **Cross-file:** `append_mesh(blend, obj_name)` appends, asserts Materials.blend materials and removes the source Library entry.
  - **Scaling a small-grid part for large grid:** `scale_mesh_keep_texel(me, k, skip_faces=...)` scales positions and multiplies the UVs of tiling-material faces (`TILING_MATERIALS`) by `k`. Painted metal and chrome then keep their texel density instead of going blurry. Atlas/Decals/Emissive faces keep their UVs. `skip_faces` leaves e.g. a barrel at 1× so you can move it separately. Uniform scaling also scales every human-scale detail (handles, vents), so a plain scale-up still looks toy-like. Prefer keeping the small part at 1× and building a larger frame around it, which is what the user chose for the large autocannon.
  - **Separate frame object:** frames built around an imported mesh go in a separate object parented to it (e.g. `GunFrame` under `TurretBase2`, `matrix_parent_inverse = Identity`). `to_mesh` would wipe the imported mesh's custom normals if you merged them.

## 2. SEUT Structure & Space Engineers Conventions
- **SEUT Structure Version (avoid "Patch BLEND File" prompt):** SEUT's `check_patch_needed()` flags a file unless: (1) every `'SEUT'` scene has `scn.seut.version >= 4`, (2) every `'SEUT'` view layer has `"Paint Color"` and `"UV Grid Overlay"` custom props, and (3) every SEUT collection (`col_type != 'none'`) has `col.seut.version >= 3`. After creating/modifying SEUT scenes, run `bpy.ops.wm.patch_blend()` (from `utils.seut_patch_blend`) and assert `not check_patch_needed()` before saving.
- **Scenes & Parenting:** Every exportable scene needs a `'SEUT'` view layer and matching `sceneType`, `gridScale`, `subtypeId`, `export_exportPath`. `Main` collections allow at most 1 unparented non-light/non-camera root (`E031`).
- **Grid Alignment:** Large grid = `2.5m`, small grid = `0.5m`, centered at `(0,0,0)`. A `3×3×3` large block spans `[-3.75, +3.75]`, so a turret base at `Z = -3.75..-1.41` is intentional—check `<Size>` before shifting.
- **Turret Subpart Quirk & Naming:**
  - `TypeId=LargeGatlingTurret` (3-stage default `<SubpartPairing>`) expects `subpart_GatlingTurretBase1` → `subpart_GatlingTurretBase2` → `subpart_GatlingBarrel`.
  - `TypeId=LargeMissileTurret` (2-stage default `<SubpartPairing>`) expects `subpart_MissileTurretBase1` → `subpart_MissileTurretBarrels` (no `Base2`; `muzzle_missile_*`, `barrel_*`, and `camera` live in `MissileTurretBarrels`).
  - In Main, `subpart_*Base1` intentionally keeps **`180°` Z-rotation** (do **not** zero it unless asked); inside subpart scenes (`Base1`/`Base2`/`Barrel`/`Barrels`), **Forward = `+Y`**, Up = `+Z`.
  - ` (L)` objects with `seut.linked == true` are viewport previews; verify real `subpart_*` empties have `seut.linkedScene` and `id_props['file']`.
  - **Single-barrel guns on the gatling type (barrel-dummy trick):** `LargeGatlingTurret` spins the `Barrel` subpart while firing. For a single barrel with a non-round muzzle brake, put the WHOLE gun, barrel included, in the Base2 mesh so it elevates without spinning. Keep the Barrel scene as a tiny (~4 cm) dummy mesh hidden inside the barrel tube, carrying `muzzle_projectile_001` at the tip. `subpart_GatlingBarrel` then only sets the effect origin: place it `|OffsetZ|` behind the muzzle on the bore axis (see effect placement below). The large `AutocannonTurret.blend` works this way. Vanilla's small `AutoCannonTurret` does the same thing in two stages, with `<SubpartPairing>` pointing both `Base2` and `Barrel` at the same subpart.
  - **Weapon effect placement (muzzle flash/smoke off from the barrel tip): fix the barrel subpart ORIGIN, not the muzzle dummy.** For turrets, the `Weapons.sbc` `<Effect ... OffsetZ="-N">` (and the `Dummy="None"` smoke) lands **N m forward of the barrel subpart's origin**. Moving `muzzle_projectile*` has no visible effect (the dummy still sets where projectiles spawn). Found on 2026-11-22 with the large/small Gatling turrets: both had tip 1.446 m from origin; vanilla −1.9 put the large flash 0.45 m past the tip and −0.9 put the small one 0.55 m inside the barrel, which matched what the user saw. Inferred from those two cases, not from game code. Don't override `Weapons.sbc` to fix it. The weapon definition is shared with vanilla/DLC reskins that have other barrel lengths, and copying it means keeping every other field in sync.
    - **Fix:** `dy = |OffsetZ| − tip_y` (tip = max local +Y of the barrel mesh). In the Barrel scene, shift the barrel mesh data and the muzzle dummy by **+dy** along Y. In the Base2 scene, shift `subpart_GatlingBarrel` by **−dy**. Apply the same changes to every ` (L)` preview copy. Assert that the world bbox in the assembled Main scene and the world positions of the `(L)` muzzles are unchanged. This is safe because the gatling barrel only spins about its own forward axis, and elevation pivots on Base2. Then **Export All Scenes** and fully restart the game, because world reload keeps cached models. `scripts/shift_barrel_origin.py -- <|OffsetZ|> [--save]` does this for `GatlingBarrel`/`muzzle_projectile*`/`subpart_GatlingBarrel`. It dry-runs without `--save`. With `--save` it saves the file it opened, so run it on the scratch copy (§3 item 11). Look up vanilla offsets in `Content\Data\Weapons.sbc`, e.g. `LargeGatlingTurret` −1.9, `SmallGatlingTurret` −0.9, `GatlingGunWarfare` −1.5.
- **Detectors & Empties:** Never rename/merge meshes referenced by `detector_*` `highlight` props (`detector_conveyor_section_*`, `ReloadFrame_*`, `detector_terminal_section_*`), never apply/zero transforms on `EMPTY` objects, and **never reparent `dummy_detector_*` empties (even to silence SEUT `W006`)**—changing a detector empty's parent/inverse matrix alters its local/exported scale and breaks in-game port/detector hitboxes. Keep `subpart_*` (and `camera`) empties at `scale=(1,1,1)` — scaling a parent mesh in Object Mode + Apply Scale leaves child empties scaled (e.g. `1.2×`), which rescales the child subpart and shifts its muzzles in-game.
- **Turret subpart clearance:** `Base1` turns with azimuth, and `Barrels`/`Base2` pitch about their empty's local X. Anything on `Base1` inside the barrels' swept |x| band clips at *some* elevation. For the shared large pedestal, the Rocket pods start at |x|≈0.48 m, so `Base1` may be at most ±0.47 m wide above deck. The pedestal top is an open hole of r≈0.85 m with a rim rising to Base1-local z≈0.22 (Rocket origin), so wide low parts must stay inside r 0.85 or above the rim. A static part may fully *enclose* a rotating hub/axle (hidden inside the mesh is fine). Run `check_clearance.py` with the real `.sbc` limits.
- **Shared turret pedestal (`GatlingTurret.blend` / `RocketTurret.blend`):** the main pedestal mesh is identical in both. The subpart origins differ: Gatling `subpart_GatlingTurretBase1` is at Z −1.4908, Rocket `subpart_MissileTurretBase1` at Z −1.6211, both with Rz 180°. When copying parts between them, `dst_local_z = src_local_z + (src_origin_z − dst_origin_z)`, so Gatling→Rocket is **+0.1302**. Verify by comparing world-space bboxes after the transform; don't trust sign arithmetic. A build once shifted the copied turntable −0.1302 (26 cm too low).
- **Pedestal style palette (to match new parts):** body `PaintedMetal_VeryDark`, light rounded shells `PaintedMetal_Colorable` (chamfered top corners, 2–3 segment bevels), top ring `MetalMilitary`, trim `PaintedMetal_Darker`, bar handles `Chrome`. In renders and in game `PaintedMetal_Darker` is barely darker than `Colorable`; use `PaintedMetal_VeryDark` for plates that must stand out. `Emissive` (glowing; color is driven by the block) is in `Materials.blend`. Link it if the file lacks it, and use it sparingly: users prefer a single deliberate emissive element (e.g. a camera iris ring) over grids of lights.
- **Build Stage (`BS*`) Collections:** For turrets, follow the Gatling/Rocket pattern. Each `BSN (<Scene>)` holds the pedestal construction mesh (`TurretConstruction_N` / `MissileTurretConstruction_N`; pedestal-only versions have 644 / 2,052 / 3,278 faces and are identical across both files) plus a head child mesh (`CIWS_BSN`, `MissileTurretHead_BSN`) parented to it with `matrix_parent_inverse = parent_world.inverted()`, all faces `Construction`. Build the head from the real subpart geometry transformed by the composed `subpart_*` empty matrices at elevation 0, roughly: BS1 = beam frame + turntable frame, BS2 = solid core + framed pods, BS3 = full shapes minus fine details. Only omit **whole closed parts** (missiles, antennas, rivets) for "unfinished" looks. Dropping an outer shell mesh (e.g. the Rocket pods' `part1`) leaves the remaining meshes open and see-through in game. Check BS renders top **and** `--bottom`. To strip an old head from a combined construction mesh, delete islands whose world max Z is above the pedestal top (−1.40). SEUT `BS` collections normally use `ref_col = None`. Assigning `bs_col.seut.ref_col` triggers SEUT's `update_ref_col` callback, which resets `type_index` to `1` and can shadow `BS1` (renaming `BS3` to `BS1 (<scene>).001`). Always set `ref_col` *before* `type_index` and `name`, and verify every scene has distinct `BS1..BSN` indices.
- **Dual-Grid Export Flag Trap:** If both `scn.seut.export_largeGrid` and `scn.seut.export_smallGrid` are `True` on a single-grid scene, SEUT writes prefixed `LG_*` / `SG_*` copies instead of updating `<Scene>.mwm`. Keep only the flag matching `gridScale` enabled, and always check `.sbc`-referenced `.mwm` timestamps and unreferenced `.mwm` files on disk after export.
- **Turret collision pattern** (applied to the large Autocannon and Gatling turrets, 2026-11-23): the turret is a fixed block with rotating subparts. Its `Collision - Main` holds:
  - **Pedestal:** a `BOX` around the pedestal only (`Collision_Box`, x/y ±1.32, z −3.75..−1.40 on the shared pedestal).
  - **Head:** a 16-sided `CONVEX_HULL` prism, `Collision_Head` (`procgen.ngon(1.0, 16)`, radius 1.0 m about the azimuth axis), from the pedestal top to the head's top at rest: +0.15 for the autocannon, +0.90 for the gatling dome.

  Leave the barrel outside, as vanilla does. Never use a full-block column: the old 2.5×2.5×7.5 box left a 3 m invisible pillar above both guns. To copy a collision object, use `obj.copy()`; that already puts the copy in `RigidBodyWorld`, so link it only to collections it isn't in yet. For a scene without a rigid body world, `bpy.ops.rigidbody.object_add()` inside `temp_override(object=…, active_object=…, selected_objects=[…])` creates the world. Script: `<scratch>\col\fix_collision.py` (session-only).
- **Collision (`Collision - Main`):** Convex primitives/hulls, applied `scale=(1,1,1)`, **MUST have a valid `UVMap`** (`MwmBuilder` runs on `<Subtype>*.fbx` including `*.hkt.fbx` and throws `E044: has no UV map/channel!` if a collision mesh lacks UVs — `bmesh.ops.create_cube` does not create UVs automatically!), no unapplied modifiers (`E034`), max 10 objects (`E022`), `display_type='WIRE'`, Rigid Body shape `BOX`/`SPHERE`/`CYLINDER`/`CONVEX_HULL` (never `COMPOUND` → `E054`). Clear any stale `col.seut.hkt_file = ""` when adding collision meshes or SEUT throws `E055`.
- **Non-DLC Materials & UVs:** Stick to vanilla materials from `Materials.blend` (`PaintedMetal_Colorable`, `PaintedMetal_Darker`, `PaintedMetal_VeryDark`, `PaintedMetal_Yellow`, `Metal_Dull`, `MetalMilitary`, `Chrome`, `PanelingColorable`, `Conveyor`, `Decals`, `Construction`; avoid `W012` DLC mats; note `Terminal` is a glowing blue keypad texture). Procedural meshes need a UV map with `<0.5%` verts at `(0,0)` (`check_uvms` `E032`/`E042`/`W002`).

## 3. Headless `.blend` Editing Pitfalls
1. **Back up cleanly & don't overwrite open files:** Keep at most one `*_original_backup.blend` + one rolling `*_latest_backup.blend` in `<scratch>` and prune old intermediate PNGs/JSONs so scratch doesn't bloat; never save over a file open in Blender (or tell the user to `File → Revert`).
2. **Guard linked `Materials.blend` & cross-`.blend` mesh reuse:** Assert all `bpy.data.libraries` paths exist via `os.path.exists(bpy.path.abspath(lib.filepath))` before saving (pass `library=img.library` when resolving linked image paths). When copying a mesh from another `.blend`, append with `bpy.data.libraries.load(path, link=False)` and immediately remap every material slot on the appended mesh to the target file's own `Materials.blend` materials (linking any missing vanilla materials directly from `Materials.blend`) so no stale cross-file library link or `.001` duplicate materials remain.
3. **Headless SEUT operators & popups:** Stub `seut_errors.show_popup_report` in `-b` mode (else `UI_popup_menu_end` access violation), and wrap `export_all_scenes`/`update_subpart_instances` in `with bpy.context.temp_override(area=view3d_area):` because `prep_context()` reads `context.area.type`. If **Update Subparts** in Blender GUI jumps to a subpart scene and says nothing, an uncaught exception occurred inside `update_linkSubpartInstances` (check **Window → Toggle System Console**; often fixed by unhiding `H`-hidden objects or unlinking/relinking subparts).
4. **Unhide `LayerCollection.hide_viewport` before `select_set`/`transform_apply`:** Hidden `BS1`–`BS3`/`Collision` layer collections silently ignore `select_set(True)`. Save/clear/restore `lc.exclude`, `lc.hide_viewport`, and `col.hide_viewport`; assert `obj.select_get()`, final transforms, and preserved `world_bbox`.
5. **Blender material slot traps (`pop()` & `clear()`):**
   - `mesh.materials.pop(index=k)` auto-decrements `poly.material_index` for all polys `>= k`. Only remap `poly.material_index == dup_i` → `first_idx` (leave `> dup_i` untouched), pop highest to lowest.
   - `mesh.materials.clear()` resets **every** `poly.material_index` to `0`! Always clear/populate `mesh.materials` **before** calling `bm.to_mesh(mesh)`, and always assert per-material polygon counts after writing.
6. **Procedural geometry Z-fighting:** Never place intersecting/adjacent boxes or concentric rings on the exact same plane or radius (e.g. X-truss plates/posts/bulkhead sharing `X=±0.34`, crossing X-diagonals with identical width, or nested collars sharing `r_inner`). Offset adjacent/crossing parts by `≥2–4mm`.
7. **Inactive-scene `matrix_world` & rendering:** `matrix_world` is stale/identity on non-active scenes—switch `bpy.context.window.scene` + `view_layer.update()` (or compose `matrix_basis`). When rendering non-active scenes in headless Cycles, also disable `scn.use_nodes`, `use_compositing`, `use_sequencer`, `use_border`, unhide collection trees, and pass `scene=scn.name` to `bpy.ops.render.render`.
8. **Custom split normals, edge-split meshes & `bmesh.ops.bevel`:** `bm.to_mesh()` wipes custom split normals (`has_custom_normals`). To delete faces from an imported mesh while keeping them, select the polygons (`p.select`) and use edit mode: `bpy.ops.object.mode_set(mode='EDIT')`, `bpy.ops.mesh.delete(type='FACE')`, back to OBJECT. This was verified on 2026-11-23: `has_custom_normals` stays True and the face count drops exactly. Editing `v.co` directly and `me.transform()` with uniform scale also keep them. and `dissolve_limit` / `DATA_TRANSFER(POLYINTERP_NEAREST)` can cause diagonal shading steps across concave 90° miter creases on curved pipes—always check grazing-light close-ups before replacing curved meshes with custom normals. Imported SE meshes often have per-face split vertices: when deleting specific sub-parts, cluster faces with a spatial-hash flood fill (do **not** run `remove_doubles` on the live mesh) so kept faces preserve their exact UVs and hard edges. After `bmesh.ops.bevel()`, filter `[v for v in verts if v.is_valid]` because beveling deletes original corner `BMVert`s. When joining meshes (`Ctrl+J`), verify all selected meshes share the exact same UV map name (`UVMap`) first so Blender doesn't create a second UV layer ignored by `MwmBuilder`.
9. **`bmesh.ops.bevel` copies face attributes:** bevel rebuilds the original faces from the originals' `material_index`, and its returned `faces` are only the new bevel strips. Set `material_index` on a primitive's faces **before** bevelling, then re-collect "all faces not present before the primitive". Otherwise big flat faces silently stay on material 0; it renders as "my dark plates look like the body". `procgen.py` does this. Probe a few large faces' material after building.
10. **Cross-file append leaves a Library:** `bpy.data.libraries.load(other.blend, link=False)` registers `other.blend` in `bpy.data.libraries` even after you delete the appended mesh. Check no ID still has `id.library == lib`, then call `bpy.data.libraries.remove(lib)` before saving. Object and mesh names usually differ (e.g. `TurretConstruction_1` object ≠ its mesh name), so load `dst.objects` and take `.data`, then remove the appended objects. `procgen.append_mesh(blend, obj_name)` does all of this. Appending an object whose name already exists (e.g. `TurretBase2` from another turret file) gives it a `.001` name; take it from `dst.objects[0]`, not by name.
11. **Scratch-copy workflow:** never edit `Models\*.blend` in place. Hash it, copy it to `<scratch>\work\` (keep `*_original_backup.blend`), build and verify on the copy, then `writeback_blend.py --expect-sha256 <hash> --backup-to <scratch>\work`. Keep the build as ONE script that rebuilds from the untouched source each iteration, removing and recreating its own objects by name, instead of patching the previous output. Each look change is then a parameter edit and a re-run. Store the scripts somewhere durable if the user may iterate later, because scratch gets cleared. If the user edits the file between turns (e.g. adds missiles), re-copy from `Models\` and re-run the build scripts on the new copy. Never write back an older scratch copy over their edits.
12. **Verify after saving:** Check `inspect_blend.py` (SEUT `check_*` all `CONTINUE`, `needs_seut_patch` false), per-material poly counts, `check_clearance.py` for turret subparts, and `render_stages.py` / `render_blend.py` (`--assemble`/`--pitch`/`--hide-linked`/`--bottom`/`--show-collision`).

    - `COL_MISSING`: no collision objects and no external `.hkt`.

### Manual review (collision fit + build-stage look)
Use this when the user wants models checked "by eye", for audit `COL_*`/`BS_*` warnings, after any collision or build-stage change, and for models the audit lists as `REVIEW_NEEDED`, `REVIEW_STALE` or `REVIEW_OPEN_ISSUES`.
```powershell
& $PY "<skill>\scripts\review_pack.py" --model "large\AutocannonTurret" --out "<scratch>\review"   # or --needs-review
```
- **Output per model:** `<out>\<model>\` gets:
  - `stages_front.png` / `stages_back.png`: [Main | BS1 | BS2 | BS3 | COL] rows for every scene
  - `<scene>_collision.png`: the assembled block with the collision in amber
  - `<scene>_final_bs.png` / `_final_bs_bottom.png`: the final stage alone, top and underside
  - `review.md`: coverage, overreach and per-object stage match numbers, plus the checklist

  It takes about 40 s for a turret. Renders run one after another per file, because parallel renders of one `.blend` fight over temp files.
- **Procedure:**
  1. Read `review.md`, then **Read every PNG**.
  2. Answer each checklist line from what you see. Collision: everything solid inside amber, no amber where there's no model, inside the block cells, and turret heads not boxed in. Stages: progression, silhouette fit, Construction grey, no holes from the back or bottom, turret head in place.
  3. Use the numbers to point at regions, e.g. "off-model geometry around z −3.47..−1.54".
  4. Report each item to the user with the image path, and propose fixes.
- **Recording the verdict:** after the user agrees, run `review_pack.py --mark <model> --status ok|issues --notes "<what was checked or what's wrong>"`. It writes `Models\review_log.json` with the file's sha256.
  - While the hash matches, an `ok` review downgrades that model's `COL_*`/`BS_*` warnings to INFO ("accepted in review"), so intentional designs don't nag every audit.
  - Any later edit turns it into `REVIEW_STALE`. An `issues` review stays a WARN (`REVIEW_OPEN_ISSUES`) until it's re-marked.
- **What can't be automated:** whether a stage looks good, and whether off-model geometry is intentional (open frames, scaffolding) or a leftover. Also mirroring, and whether a turret head should get its own subpart collision.
